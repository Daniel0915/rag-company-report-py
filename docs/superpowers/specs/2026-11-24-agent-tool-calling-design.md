# 에이전트 도구 호출(Agent Tool Calling) 설계

작성일: 2026-11-24 · 대상 저장소: `rag-company-report-py` · 브랜치: `feat/agent-tools`

## 왜 만드나

**답변 품질을 올리기 위해서다**(사용자 결정). 지금 채팅은 질문마다 공시 벡터 검색을 한 번 하고, 상위 청크로 답한다. 첫 평가 기준선(`eval/runs/20261121-011143_local_k6.json`, 삼성전자 32문항)에서 이 방식의 한계가 숫자로 드러났다.

- 핵심 사실 포함률(`fact_recall`) 0.248. 숫자 질문에서 근거 청크가 엉뚱하거나, 계산(증감·차액)을 틀린다.
- 정답 위치를 엄격 기준으로 찾은 비율(`hit_strict`) 0.375. 한 번의 검색으로는 맞는 섹션에 닿지 못하는 질문이 많다.
- 공시가 아직 수집되지 않은 기업(2026-11-24 기준 8곳)은 아예 답할 근거가 없다.

모델이 질문에 맞는 도구(공시 검색, 재무 수치, 공시 목록, 그래프, 계산, 웹검색)를 골라 여러 번 쓰게 하면 이 문제들을 직접 다룰 수 있다. 참고 자료는 Stanford CS329Z Lecture 4 "Tool Use"이다.

이 작업은 평가(`2026-11-19-rag-eval-design.md`) 위에서 진행한다. 개선 여부는 같은 정답셋으로 기존 방식과 에이전트 방식을 `compare`해서 판단한다.

## 목표, 비목표, 반목표

**목표**
1. 도구 6개를 파이썬 함수로 한 번만 구현하고, 두 답변 모델에 연결한다.
   - 로컬(Ollama): Function Calling(`/api/chat`의 `tools`)으로 우리 코드가 루프를 돈다.
   - Claude(로그인된 `claude` CLI): 같은 함수를 감싼 MCP 서버(stdio)를 `--mcp-config`로 붙인다. 루프는 CLI 안에서 돈다.
2. 기존 고정 방식(검색 한 번 → 답변)은 그대로 두고, 에이전트 방식을 옵션으로 추가한다.
3. 평가 CLI로 두 방식을 같은 정답셋에서 비교할 수 있게 하고, 도구 사용 지표를 더한다.

**비목표**
- 모델 학습이나 미세조정. Toolformer식 "도구 가중치"는 학습 시점의 개념이라 다루지 않는다. 도구 우선순위는 도구 설명과 시스템 프롬프트 규칙으로 조절한다.
- Claude API(종량제)와 LangGraph 같은 에이전트 프레임워크. 구독 CLI를 유지하기로 했다(사용자 결정). CLI는 자체 루프를 돌리므로 프레임워크가 끼어들 자리가 없다.
- 화면(프론트엔드) 변경. 화면 소스가 이 저장소에 없다. 응답에 도구 기록을 추가하되 화면에는 1차에서 표시하지 않는다.
- 대화 히스토리가 있는 후속 질문의 에이전트 처리. 1차는 단일 질문만 에이전트로 처리한다. 히스토리가 있으면 기존처럼 질문을 재작성한 뒤, 재작성된 질문으로 에이전트를 돌린다.
- 로컬 모델 교체와 사양 결정. 나중에 따로 정한다(사용자 결정).
- 데이터 수집 마무리. 별도 Claude 세션에서 메인 체크아웃으로 진행 중이다.

**반목표** (돌아가도 실패로 보는 경우)
- 기존 채팅 API의 동작이나 응답 형식이 바뀌는 것(에이전트 옵션을 켜지 않은 요청 기준).
- `ANTHROPIC_API_KEY`를 쓰거나 요구하는 것.
- Tavily 키가 저장소나 로그, 결과 파일에 남는 것.
- 공시에 근거가 있는데도 웹검색 결과로 답하는 것. 웹 출처가 공시 출처인 것처럼 보이는 것.
- 도구를 끝없이 부르거나, 실패한 호출을 같은 인자로 반복하는 것(슬라이드 67의 Recovery 실패).

## 제약

- **과금/인증:** Claude는 `claude` CLI(구독 로그인)로만 부른다(`CLAUDE.md`). Tavily 키는 `.env`의 `TAVILY_API_KEY`에만 둔다(이미 메인 체크아웃과 이 작업 폴더의 `.env`에 들어 있고, `.env`는 `.gitignore`에 있다). `.env.example`에는 빈 값으로만 추가한다.
- **CLI 동작:** `claude -p`는 `--mcp-config`, `--strict-mcp-config`, `--allowedTools`, `--output-format stream-json`(`--verbose`와 함께)을 지원한다. 이 CLI 버전의 `--help`에는 최대 턴 수 옵션이 없다. 그래서 도구 호출 한도는 MCP 서버 쪽에서 센다.
- **로컬 모델:** 지금은 `qwen2.5:3b`(Ollama 도구 호출 지원)이다. 입력이 약 2K 토큰에서 잘리는 문제가 있다(기준선에서 26/32문항). 에이전트 경로는 도구 설명과 도구 결과가 붙어 입력이 더 길어지므로, 에이전트용 Ollama 호출에는 `num_ctx`를 키운 옵션을 쓴다. 기본값은 16384이다(설계자 판단, 설정으로 바꿀 수 있게). 채팅의 고정 경로 옵션은 바꾸지 않는다.
- **데이터:** 22개 기업 중 13곳은 공시 수집이 끝났고, 기아는 거의 끝났고, 8곳은 수집 중이다. 도구는 데이터가 없는 기업에서도 오류 없이 "없음"을 돌려줘야 한다.
- **실행 환경:** Neo4j(Docker), Ollama가 켜져 있어야 한다. MCP 서버는 CLI가 요청마다 자식 프로세스로 띄운다. 따라서 Neo4j 연결과 임베딩 클라이언트를 MCP 서버 프로세스 안에서 새로 만든다.

## 접근 방식

| 결정 | 고려한 방식 | 선택과 이유 |
|---|---|---|
| 모델 연결 | A. 도구 한 벌 + 로컬은 Function Calling, Claude CLI는 MCP / B. 로컬 모델만 Function Calling / C. 프롬프트에 도구 목록을 넣고 JSON 응답을 직접 파싱(모든 모델 공통) | **A**(사용자 결정: 구독 CLI 유지). B는 품질 상한이 3B 모델에 묶인다. C는 도구를 한 번 부를 때마다 `claude -p`를 새로 띄워 느리고, 모델의 기본 도구 호출을 못 써서 형식 오류가 늘어난다. Claude CLI에 도구를 주는 공식 경로는 MCP뿐이다. |
| 과금 | 구독 CLI / Claude API | **구독 CLI**(사용자 결정). API였다면 Function Calling 하나로 통일하고 서버 웹검색 도구와 LangGraph를 쓸 수 있었지만, 종량제 과금이 생긴다. |
| 웹검색 | Claude CLI 내장 웹검색 / 네이버 수집 / Tavily API | **Tavily**(사용자 결정, 키 제공). 두 모델이 같은 웹검색 도구를 써야 평가 조건이 같다. 그래서 CLI 내장 웹검색은 끈다. |
| 프레임워크 | LangGraph / 직접 구현 | **직접 구현.** Claude 경로의 루프는 CLI 안에 있고, 우리가 돌리는 루프는 로컬 경로뿐(최대 6회)이라 프레임워크 의존성에 비해 얻는 게 적다. |
| 기존 방식 | 대체 / 공존 | **공존.** 에이전트 방식은 옵션이다. 평가로 나아짐을 확인한 뒤에 기본값을 바꾼다. |

## 도구 (1차 6개)

모든 도구는 `app/agent/tools.py`(가칭)에 순수한 파이썬 함수로 둔다. 입력은 JSON 스키마로 설명할 수 있는 단순한 값이고, 출력은 모델에게 줄 텍스트와 출처 메타데이터(구조화)를 함께 담은 결과 객체다. 두 연결 방식(Function Calling, MCP)은 이 함수와 스키마를 그대로 쓴다. 도구 정의가 한 곳에만 있어야 한다.

| 도구 | 하는 일 | 데이터 출처 |
|---|---|---|
| `search_disclosures(query, corp_code, doc_type?, top_k?)` | 기업별 벡터 인덱스 검색. `doc_type="NEWS"`이면 뉴스만 찾는다. | Neo4j 벡터 인덱스(지금의 `CompanyChatService.retrieve`를 재사용) |
| `get_financials(corp_code, year, report)` | 매출액, 영업이익, 당기순이익 같은 주요 계정의 정확한 수치. `report`는 사업/반기/1분기/3분기. | DART Open API 재무정보(예: 단일회사 주요계정 `fnlttSinglAcnt.json`). 정확한 엔드포인트와 계정 선택은 빌더에게 맡긴다. |
| `list_recent_disclosures(corp_code, since?, types?, limit?)` | 공시 목록을 접수일 최신순으로(보고서명, 접수번호, 접수일, 유형). | Neo4j `Report` 노드(`FILED_BY` 관계) |
| `query_ownership_graph(cypher)` | 지분공시 제출인 관계의 집계·랭킹·교집합. | 에이전트 모델이 Cypher를 직접 쓰고, 도구는 읽기 전용으로 실행만 한다(`run_read_only_query` 재사용, `WRITE_CLAUSE` 차단 그대로). 그래프 스키마와 현재 기업의 `corp_code`는 도구 설명에 넣는다. |
| `calculate(expression)` | 사칙연산, 증감률, 차액. | 안전한 산술 평가(파이썬 `eval` 금지, AST로 허용된 연산만) |
| `web_search(query, max_results?)` | 공시에 없는 정보를 웹에서 찾는다. 제목, 요약, URL을 돌려준다. | Tavily Search API(`TAVILY_API_KEY`) |

공통 규칙:
- `corp_code`는 워치리스트(`app/watchlist.py`)에 있는 기업만 받는다. 없으면 도구 오류로 돌려준다(예외를 던지지 않는다). 기본값은 채팅 요청의 기업이다.
- 도구 결과가 비면 "결과 없음"을 분명히 돌려준다. 그래야 모델이 다른 도구로 넘어가거나 모른다고 답한다.
- 도구 하나의 실패(타임아웃, DART 오류, Tavily 오류)는 그 호출의 오류 결과로 돌려주고, 질문 전체를 멈추지 않는다.
- 도구 결과 텍스트에는 길이 상한을 둔다. 모델 입력이 넘치지 않게 하기 위해서다. 상한 값은 빌더에게 맡긴다.

`query_ownership_graph`가 질문 대신 Cypher를 받는 이유(설계자 판단): 지금 Text2Cypher는 답변 provider가 Cypher를 쓴다. 이걸 질문을 받는 도구로 옮기면, Claude 경로에서는 MCP 서버(이미 `claude -p`의 자식 프로세스)가 다시 `claude -p`를 띄워야 한다. 느리고 구독 사용량이 늘며 타임아웃에 걸리기 쉽다. 반대로 Ollama로 고정하면 두 경로의 조건이 달라진다. 에이전트 모델이 Cypher를 직접 쓰면 도구 안에 LLM 호출이 없어 결정적이고 단위 테스트하기 쉽다. 잘못된 Cypher는 오류 결과로 돌려주고, 모델이 고치거나 다른 도구로 넘어간다. 고정 경로의 VectorCypher 폴백은 에이전트 경로에서 쓰지 않는다. 대가는 3B 로컬 모델이 Cypher를 잘 못 쓴다는 점인데, 로컬은 비교용이라 받아들인다.

### 도구 우선순위 (시스템 프롬프트 규칙)

"도구 가중치"는 학습 개념이라 쓰지 않고, 아래 규칙을 시스템 프롬프트와 도구 설명에 넣는다.
1. 공시 도구(`search_disclosures`, `get_financials`, `list_recent_disclosures`, `query_ownership_graph`)를 먼저 쓴다.
2. `web_search`는 공시 도구로 근거를 찾지 못했거나, 공시에 없는 정보(주가, 업계 동향 등)를 물을 때만 쓴다.
3. 숫자를 계산할 때는 `calculate`를 쓴다.
4. 답변에는 근거 출처를 밝히고, 웹 출처는 "웹" 출처로 구분해 표시한다.
5. 근거가 없으면 지어내지 말고 모른다고 답한다.

## 실행 흐름

### 로컬 경로 (Function Calling)
1. 시스템 프롬프트, 질문, 도구 스키마를 `/api/chat`(`tools`)에 보낸다.
2. 응답에 `tool_calls`가 있으면 해당 도구를 실행하고, 결과를 `role: "tool"` 메시지로 붙여 다시 보낸다.
3. 도구 호출이 없는 응답이 오면 그게 최종 답이다.
4. 도구 호출은 질문당 최대 6회다. 6회를 넘기면 도구 없이 지금까지의 근거로 답하라는 지시를 붙여 한 번 더 부른다.
5. 같은 도구를 같은 인자로 두 번째 부르면, 실행하지 않고 "같은 호출을 반복했다"는 오류 결과를 돌려준다.

`OllamaClient`에는 메시지 목록과 도구 스키마를 받아 `tool_calls`를 돌려주는 메서드를 하나 더 둔다. 기존 `generate()`와 `chat()`의 반환형은 바꾸지 않는다.

### Claude 경로 (MCP)
1. 요청마다 MCP 설정 JSON(임시 파일)을 만든다. stdio 서버 명령은 이 저장소의 파이썬으로 `python -m app.agent.mcp_server`(가칭)를 실행하는 것이다. 이 설정은 `--mcp-config`로 넘긴다.
2. `claude -p`를 다음 옵션으로 부른다: `--strict-mcp-config`(사용자의 다른 MCP 서버를 막는다), `--allowedTools`(우리 도구 6개만, CLI 내장 도구는 모두 막는다. 웹검색 포함), `--output-format json`, `--system-prompt`(위 규칙). 최종 답변은 CLI 출력에서 읽는다.
3. **도구 기록은 별도 파일로 받는다(설계자 판단).** 요청마다 임시 트레이스 파일 경로를 만들어 MCP 설정의 환경변수로 서버에 넘긴다. MCP 서버는 도구를 실행할 때마다 한 줄(JSON Lines)씩 기록한다: 순서, 도구 이름, 인자, 성공 여부, 모델에게 준 결과 텍스트, 구조화된 출처 메타데이터(청크의 `rcept_no`·`source_file`·`section_order`·`section_title`·`score`, 웹 결과의 제목·URL 등). CLI가 끝나면 이 파일로 응답의 `sources`, `toolCalls`, 평가의 검색 지표를 만든다. 이유: 출처 메타데이터를 모델이 보는 결과 텍스트에 넣으면 입력이 길어지고, CLI의 `stream-json` 이벤트 형식에 기대면 CLI 버전에 따라 깨질 수 있다. 파일 방식은 CLI 출력 형식과 무관하고, 로컬 경로도 같은 기록 형식을 쓰면 두 경로의 평가 계산이 하나로 통일된다.
4. 도구 호출 한도(6회)와 반복 호출 차단은 MCP 서버가 프로세스 안에서 센다. 한도를 넘기면 "한도 초과, 지금까지의 근거로 답하라"는 오류 결과를 돌려준다.
5. 에이전트 경로의 Claude 호출 타임아웃은 기존 60초보다 길게 잡는다. 기본값은 180초이다(설계자 판단, 설정 가능).

MCP 서버는 공식 `mcp` 파이썬 SDK(FastMCP)로 만든다. 도구 함수를 그대로 감싸고, 스키마는 도구 정의에서 가져온다.

## API 변경

- `ChatRequest`에 `agent: bool = False`를 추가한다. `false`이면 지금과 완전히 같은 경로를 탄다.
- `ChatResponse`에 선택 필드 `toolCalls: list[ToolCallTrace] | None`을 추가한다(이름, 인자, 성공 여부, 결과 요약). 고정 경로에서는 `None`이다.
- 웹 출처는 `SourceItem(docType="WEB", reportNm=제목, rceptNo=URL)`로 넣는다. 뉴스 출처가 `rceptNo`에 기사 URL을 넣는 지금 규칙과 같다(설계자 판단).
- 화면은 1차에서 바꾸지 않는다. 지금 화면은 `agent`를 보내지 않으므로 기존 동작 그대로다.

## 평가 통합

- `python -m app.eval run`에 `--agent`를 추가한다. 결과 파일의 `config`에 `agent` 값을 남긴다.
- 에이전트 실행 결과의 문항 행에 `tool_calls`(도구 이름·인자·성공 여부·순서)를 남긴다.
- 검색 지표(`hit_strict`, `hit_loose`, `mrr`)는 그 문항에서 `search_disclosures`가 돌려준 청크를 호출 순서대로 이어 붙인 목록으로 계산한다. `search_disclosures`를 한 번도 안 불렀으면 빈 목록으로 본다(설계자 판단).
- `unsupported_numbers`의 근거 텍스트에는 모든 도구 결과 텍스트를 넣는다(웹검색, 재무 수치 포함).
- 새 지표:

  | 지표 | 정의 |
  |---|---|
  | `tool_selection` | 문항의 `expected_tools` 중 하나라도 썼으면 1. `expected_tools`가 없는 문항은 제외. |
  | `unnecessary_web` | `expected_tools`에 `web_search`가 없는데 웹검색을 했으면 1. 낮을수록 좋다. |
  | `tool_errors` | 오류 결과로 끝난 도구 호출 수 |
  | `tool_calls` | 도구 호출 수 |

- 정답셋 문항에 선택 필드 `expected_tools: list[str]`를 추가한다. "이 중 하나라도 쓰면 된다"는 뜻이다. 기존 32문항은 1차에서 이 필드를 비워 두고, 도구 지표는 값을 채운 문항에서만 센다. 값을 채우는 일은 사용자 검수 대상이다.
- `compare`의 방향 표시에 새 지표를 넣는다(`tool_selection`은 높을수록, `unnecessary_web`·`tool_errors`는 낮을수록 좋음, `tool_calls`는 표시 없음).
- 완료 기준: 같은 정답셋에서 `--agent` 없이 한 실행과 `--agent`로 한 실행을 `compare`해 결과 파일 두 개를 남긴다. 에이전트가 기존보다 나아야 한다는 것은 완료 기준이 아니다. 비교할 수 있게 만드는 것이 완료 기준이다.

## 테스트

- 도구 함수: Neo4j·DART·Tavily를 가짜로 바꿔 단위 테스트한다(빈 결과, 워치리스트 밖 기업, API 오류, `calculate`의 금지 구문).
- 로컬 루프: 가짜 Ollama가 정해진 `tool_calls`를 돌려주게 해서 실행 순서, 6회 한도, 반복 호출 차단, 최종 답을 확인한다.
- Claude 경로: CLI 명령 조립(옵션, MCP 설정 JSON)과 트레이스 파일 읽기를 단위 테스트한다. 실제 CLI 호출은 수동 스모크로만 확인한다. 스모크에서 트레이스 파일에 도구 호출이 실제로 기록되는지 꼭 확인한다.
- MCP 서버: 도구 목록(`tools/list`)이 6개이고 스키마가 도구 정의와 같은지 테스트한다.
- 기존 테스트(174개)는 그대로 통과해야 한다.
- Tavily 키가 로그에 남지 않는지 확인하는 테스트를 하나 둔다(요청 로그에서 키 가리기는 공시 수집의 `redact`와 같은 방식).
