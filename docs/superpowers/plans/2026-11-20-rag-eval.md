# RAG 답변 평가(Eval) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공시 유형별로 문항을 할당한 고정 정답셋으로 챗봇의 검색과 답변을 채점하고, 실행 결과를 파일로 남겨 두 실행을 비교하는 `python -m app.eval` CLI를 만든다.

**Architecture:** `CompanyChatService.chat()`을 `retrieve()`와 `answer()`로 나눠 평가가 실제 채팅과 같은 경로를 타게 한다. 평가 코드는 `app/eval/` 패키지에 두고, 채점·비교·정답셋 처리·샘플 선택은 LLM과 Neo4j 없이 테스트되는 순수 함수로 만든다. Neo4j 조회와 LLM 호출은 `generate.py`, `runner.py`의 얇은 바깥층에만 둔다.

**Tech Stack:** Python 3.11+, neo4j 드라이버, httpx, PyYAML, pytest, 로그인된 `claude` CLI

**Spec:** `docs/superpowers/specs/2026-11-19-rag-eval-design.md`

## Global Constraints

- Anthropic API 키를 쓰거나 요구하지 않는다. Claude는 `ClaudeCliClient`(로그인된 `claude` CLI)로만 부른다(`CLAUDE.md`).
- 평가용 Claude 호출(문항 생성, 채점)의 타임아웃은 **180초**. 답변 provider가 `claude`일 때의 답변 호출은 운영 설정(60초)을 그대로 쓴다.
- 채팅 API의 동작과 응답 형식(`ChatResponse`)은 바꾸지 않는다. `OllamaClient.generate()`의 반환형(`str`)도 바꾸지 않는다.
- `run`의 Ollama 기본값은 **temperature 0, seed 42**. `--temperature`, `--seed`로 바꾸고, 실제 쓴 값은 결과 파일에 남긴다. 채팅 API의 Ollama 호출에는 옵션을 넣지 않는다.
- 기본 문항 할당: `{"A": 12, "I": 8, "B": 5, "D": 3, "J": 1, "E": 1}` (합 30).
- 섹션 키: `(rcept_no, source_file, section_order)`. `section_order`는 정수로 비교한다.
- 청크의 공시 유형: `metadata.pblntf_ty`, 없으면 `Report.pblntf_ty`(`metadata.rcept_no`로 찾음), 둘 다 없으면 뽑지 않는다.
- 생성 대상 청크: `metadata.doc_type`이 없고, 텍스트가 **200자 이상**.
- 뉴스(`doc_type=NEWS`)와 대화 히스토리는 평가하지 않는다.
- 파일: 정답셋 `eval/dataset.yaml`, 후보 `eval/candidates.yaml`(둘 다 커밋), 결과 `eval/runs/`(`.gitignore`).
- 단위 테스트는 Neo4j·Ollama·claude CLI 없이 돈다.

## Review Focus

1. **답변에 `[1]` 같은 근거 번호나 목록 번호가 들어 있는 경우**: `unsupported_numbers`가 이것을 지어낸 숫자로 세면 안 된다. → Task 3 `test_unsupported_numbers_ignores_single_digits_and_question_numbers`
2. **Claude가 JSON을 코드 펜스(```json)로 감싸거나 앞뒤에 설명을 붙인 경우**: 생성과 채점 둘 다 JSON을 꺼내 파싱해야 한다. 그래도 안 되면 그 청크/문항만 건너뛴다. → Task 4 `test_parse_generation_accepts_fenced_json`, Task 5 `test_parse_judge_accepts_text_around_json`
3. **어떤 기업에 B 유형 공시가 아예 없는 경우**: 생성이 멈추지 않고 모자란 개수를 A에서 채우고, 유형별 실제 개수를 출력해야 한다. → Task 4 `test_pick_by_quota_fills_shortfall_from_A`

5. **문항 하나에서 Ollama 타임아웃 같은 오류가 난 경우**: 실행은 이어지고, 그 문항은 오류로 기록되고 지표 분모에서 빠져야 한다. → Task 6 `test_errored_item_is_excluded_from_denominators`

  - `@dataclass(frozen=True) class Retrieved: rcept_no: str; source_file: str; section_order: int; section_title: str; score: float | None; text: str` 와 `key` 프로퍼티
  - `hit_strict(retrieved: list[Retrieved], expected: list[Section]) -> int`
  - `hit_loose(retrieved, expected) -> int`: 엄격 일치이거나, `section_title`이 기대 섹션 중 하나와 같으면 1
  - `mrr(retrieved, expected) -> float`: 엄격 일치가 처음 나온 순위(1부터)의 역수, 없으면 0.0
  - `fact_recall(answer: str, must_include: list[str]) -> float`: 양쪽에서 공백과 쉼표를 지우고 부분 문자열 비교
  - `is_refusal(answer: str) -> bool`
  - `extract_numbers(text: str) -> set[str]`: 정규식 `\d[\d,]*(?:\.\d+)?`, 쉼표 제거. 한 자리 정수는 버린다.
  - `unsupported_numbers(answer: str, context_texts: list[str], question: str) -> int`: 답변 숫자 중 근거 숫자에도 질문 숫자에도 없는 것의 개수
  - `score_item(item: Item, retrieved: list[Retrieved], answer: str) -> dict[str, float | int]`: 답 있는 문항은 `hit_strict, hit_loose, mrr, fact_recall, false_refusal`(0/1), 답 없는 문항은 `correct_refusal`(0/1), 둘 다 `unsupported_numbers`
  - `aggregate(rows: list[dict]) -> dict[str, dict[str, float | int]]`: 각 행은 `{"metrics": {...} | None, ...}`. `metrics`가 `None`(오류)인 행은 빼고, 지표마다 그 지표를 가진 행만으로 `{"mean": 평균, "n": 분모}`를 만든다. `prompt_tokens`가 있는 행은 그것도 평균 낸다.
  - `aggregate_by_type(rows) -> dict[str, dict]`: 행의 `pblntf_ty`(답 없는 문항은 `"없음"`)별로 `aggregate`

  - `fetch_texts(driver, corp_code: str, chunk_ids: list[str]) -> dict[str, str]`
